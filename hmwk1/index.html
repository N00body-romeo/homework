Task

Multiply the base point by the private key

A private key is a number k. The public key is the point Q = k·G, where G is a fixed point on the curve and k·G means G added to itself k times with the curve's own addition rule. The curve is small enough to follow every step.

17 on the lattice, plus the point at infinity O (18 in total)

Group law, mod 17

  • λ = (y₂ − y₁) / (x₂ − x₁)P ≠ Q: slope of the chord through both points
  • λ = 3x₁² / (2y₁)P = Q: slope of the tangent (the curve has a = 0)
  • x₃ = λ² − x₁ − x₂x of the sum
  • y₃ = λ(x₁ − x₃) − y₁y of the sum

Division means multiplying by the modular inverse. If x₁ = x₂ and y₁ + y₂ ≡ 0, the sum is the point at infinity O.

Task · faster method

Double-and-add for large k

Adding G one step at a time takes k − 1 additions. Writing k in binary needs only about log₂k doublings plus one addition for every 1 bit: start with R = G, then for each remaining bit double R and, when the bit is 1, add G. A real Ethereum key has 256 bits and is around 10⁷⁷, so only this method is possible there.

Optional · guru level

The group law, one move at a time

Over F₁₇ a line is the set of 17 lattice points with y ≡ λ(x − x₁) + y₁ (mod 17). Each addition has four stages: pick the two operands, draw the line through them, find the third point where the line meets the curve, then reflect that point across the mirror y ↔ 17 − y. The reflected point is the sum.

Statistical exploration · repeating the experiment

Same k, every valid base point

Changing k above gives a different Q for the same G. Changing G gives a different Q for the same k. The curve has 17 points besides O, and each one can serve as a base point. A base point of order n only has n different multiples, so k is reduced mod n.

Base point GOrder of GQ = kG

The highlighted row is the base point selected in the parameters. The curve has 18 points including O and the group is cyclic: 6 base points have order 18, 6 have order 9 (like G = (1, 5)), 2 have order 6, 2 have order 3 and 1 has order 2. A point of order n has only n different multiples, so a useful private key is a number from 1 to n − 1.

Statistical exploration

Does kG look random?

Compute kG for every k and measure the points that come out. The homework curve has only 18 points, so its statistics are noisy. Two larger curves with the same equation and a prime number of points give the tests something to measure. Points of order 2 and 3 are left out of the base-point list because they have too few multiples to analyse.

Discussion

One-way function or hash function?

The map k ↦ kG is easy to compute and believed to be hard to invert, which is the definition of a one-way function. It also looks random in several of the statistical tests above, which makes it resemble a hash function. The tests separate what matters for a one-way function from what is specific to hashes.

PropertyWhat the experiments show for k ↦ kGOne-way functionHash function
Easy forward, hard backward Double-and-add needs about 1.5 · log₂k operations. Recovering k from Q means solving the elliptic-curve discrete-log problem (ECDLP). On the toy curve brute force finishes at once, on secp256k1 the best generic attack needs about 2¹²⁸ steps. Defining property Same idea, called preimage resistance
Determinism The same k always gives the same Q. Required Required
Distribution of x and y Roughly flat when binned. The structure is exact: only about half of the x values occur, each with y and p − y, and when p ≡ 1 (mod 3) only a third of the y values occur. Helpful, not sufficient. k ↦ c·k mod n is perfectly flat and trivial to invert. Design goal. Output bits should be indistinguishable from random.
Bit balance The top bits of x and y are biased because coordinates are below p, and not every x is a valid coordinate. Not required Design goal
Correlation of input and output Linear correlation is near zero, yet strong algebraic relations hold: (a + b)G = aG + bG and (n − k)G = −kG, so kG and (n − k)G share the same x. Structure is useful. It powers ECDH key exchange, signatures and wallet key derivation. Fatal flaw. A hash must have no usable relation between outputs.
Avalanche effect Flipping one bit of k changes about half of the output bits on average, but nothing in the construction is designed to mix bits: adding 1 to k simply adds the fixed point G to the output. Not required Design goal (strict avalanche criterion).
Collision resistance The map is injective on 1 to n − 1, so valid private keys never collide. It also takes only fixed-size inputs. Not applicable Required. A hash compresses any input to a short digest.

Statistical tests can only fail a candidate. A function that passes every test can still be easy to invert, so hardness has to come from a mathematical argument such as the ECDLP. Ethereum uses both tools in sequence: elliptic-curve multiplication turns the private key into a public key, and Keccak-256 then turns the public key into a short address.
